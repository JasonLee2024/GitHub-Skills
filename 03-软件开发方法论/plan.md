# 计划模式 — Plan Mode

> 本文档基于 Hermes Agent 的 `plan` 技能整理，描述如何在不执行代码的情况下制定可执行的实现计划。

## 概述

Plan Mode（计划模式）是 Hermes Agent 的一种特殊工作模式：**只计划，不执行**。在计划模式下，Agent 可以检查仓库、阅读上下文、分析需求，但不得修改任何项目文件（除了保存计划文档本身），也不得运行修改性的终端命令。

这种模式的核心价值在于：**在动手之前先想清楚**。当任务复杂、需求模糊或涉及多个步骤时，直接进入实现阶段容易走偏或遗漏关键细节。先制定计划可以确保方向和目标一致。

## 触发条件

计划模式通常在以下场景激活：

- 用户明确使用 `/plan` 指令
- 用户说"先制定一个计划"、"规划一下"等
- 任务涉及多个步骤、多个文件或多个团队
- 需求不明确，需要先梳理目标和方案

## 核心行为

进入计划模式后，Agent 必须遵守以下规则：

1. **不实现代码** — 不得编写任何实现代码
2. **不编辑项目文件** — 除非是保存计划文档本身
3. **不运行修改性命令** — 不 commit、push、或执行外部操作
4. **允许只读操作** — 检查仓库结构、阅读文件、搜索代码
5. **交付物是计划文档** — 一个 markdown 计划文件

## 计划文档的内容要求

计划文档应包含以下信息（根据任务灵活调整）：

| 章节 | 内容 |
|------|------|
| **目标** | 一句话描述要做什么 |
| **当前上下文** | 现有代码库状态、假设条件 |
| **技术方案** | 选择的架构/方法及其理由 |
| **分步计划** | 每一步做什么，精确到文件路径 |
| **可能修改的文件** | 创造、修改、删除的文件列表 |
| **测试与验证** | 如何验证每个步骤的正确性 |
| **风险与权衡** | 潜在问题和备选方案 |

## 计划的粒度

好的计划应当是**具体且可执行的**：

- 每个任务 2-5 分钟的工作量
- 精确的文件路径（如 `src/models/user.py` 而不是 "模型文件"）
- 包含完整的代码示例（可直接复制粘贴）
- 包含精确的命令和期望的输出
- 包含验证步骤

**过粗的计划：**

```
Task 1: 实现用户认证系统
```

**合适的粒度：**

```
Task 1: 创建 User 模型（email 和 password_hash 字段）
  → tests/models/test_user.py: 写测试
  → src/models/user.py: 编写实现
  → pytest 验证

Task 2: 添加密码哈希工具函数
  ...
```

## 保存位置

计划文档保存在项目工作区下的 `.hermes/plans/` 目录中：

```
.hermes/plans/2026-05-05_120000-feature-name.md
```

文件名使用时间戳加描述性 slug，确保唯一且可排序。

## 与其它方法论的关系

计划模式是整个开发流水线的**起点**：

```
Plan → TDD → Implement → Code Review → Debug → Analyze
```

- **Plan** 的输出作为 **Writing Plans** 风格的详细实现计划
- 详细计划通过 **Subagent-Driven Development** 执行
- 每个步骤遵循 **TDD** 的 RED-GREEN-REFACTOR 循环
- 完成后经过 **Code Review** 验证
- 遇到 bug 时使用 **Systematic Debugging** 分析

## 常见问题

### Q: 什么时候该用 Plan Mode？

A: 任何涉及 3 个以上文件修改、或工作步骤超过 5 步的任务都建议先计划。简单的修复或单文件改动可以直接实现。

### Q: 计划写完后必须照做吗？

A: 计划是指导性文档，不是不可变的。实施过程中发现更好的方案，应该更新计划再继续。

### Q: 计划和 Writing Plans 有什么区别？

A: Plan Mode 是一个"模式开关"（只计划不执行），而 Writing Plans 是一种"计划撰写方法论"（如何写出好的计划）。Plan Mode 可以运用 Writing Plans 的方法论来撰写高质量计划。
